# 六步主流程与补充环节的逐步注解

来源：2026-10-17，用户逐条提出六步流程，接受补充项，并要求以后所有 3D 打印建模任务默认采用。以下将流程映射到本机操作，未增加自动启动打印权限。

| 步骤 | 输入 | AI 要做的事 | 输出与注解 |
|---|---|---|---|
| 1. 用户提出需求 | 目的、参考、已有零件/项目 | 确认用途和约束，记录原话 | 需求记录；不要把“开始讨论”理解成批准建模 |
| 2. 选择软件 | 几何特点和精度要求 | 参数化/机械选 Fusion，雕刻选 Blender；先检查 MCP | 软件和理由；用户指定优先，连接失败先恢复 |
| 3. 确定细节 | 尺寸、外观、修改要求 | 协商结构、拆件、公差、打印机/喷嘴/材料和效果优先级 | 需求与方案文档；关键尺寸缺失时先问 |
| 4. 生成效果图 | 已明确方案 | 出图、展示、按反馈调整 | 需求+效果图一起提交 `design`，用户确认后才建模 |
| 5. 建模与最终模型确认 | 已确认方案 | 建模、几何检查、保存源文件、展示真实模型；修改后复查 | 源文件+STL+实际截图+报告提交 `model`；确认后导入 Bambu |
| 6. 调参、支撑与质量检查 | 已确认模型及用户打印条件 | 设置、切片、看真实路径，检查支撑易拆、首层和稳定性等 | 3MF 工程、检查记录、关键层截图；需要改结构返回步骤5 |
| 补充7. 最终切片确认 | 切片预览与审查结果 | 解释时间、耗材、剩余风险 | 已切片3MF+审查文档等提交 `slice`，等待明确同意 |
| 补充8. 归档和实物反馈 | 三次有效确认 | 打包、记录版本，收集打印与装配结果 | 完整包、SHA-256、说明、实物反馈；启动打印另行授权 |

## 三个容易混淆的地方

1. **效果图和真实模型**：效果图用于外观沟通；最终模型必须以实际 CAD/网格预览确认。
2. **支撑设置和实际支撑**：开启支撑、涂上颜色不等于支撑已经生成。必须重新切片，检查实际路径和拆除空间。
3. **软件验证和实物验证**：闭合网格与 G-code 不证明粘附、翘边、强度、尺寸精度或装配一定成功。

## 修改后的回退

- 需求、外观方向变化：重新提交 `design`，清除下游旧确认。
- 结构、尺寸、部件变化：修改模型、复查、重新提交 `model`，再次取得用户确认。
- 朝向、支撑、参数变化：重新切片、检查、重新提交 `slice`。
- 未变化且前序有效的阶段不要求用户重复确认。

## 代码注解对应关系

- `scripts/workflow.py`：`initialize` 对应需求准备；`submit`/`confirm` 对应三个确认节点；`open_bambu` 对应模型到切片的交接；`slice_project` 对应重新切片；`package` 对应最终归档。
- `scripts/mesh_check.py`：模型确认前的基础网格检查。STL 无内置单位，尺寸必须与 CAD 核对；最小壁厚、自相交及配合不在该脚本覆盖范围内。
- `scripts/bambu.py`：读取实际 3MF 配置、G-code 和估算；只运行本机切片，保留用户配置项目的设置。
- `scripts/templates`：需求、切片审查和实物反馈模板，空白项不代表通过。

## 确认记录的含义

`submit` 保存文件 SHA-256；`confirm` 记录用户实际答复。脚本检查哈希及前序阶段，但无法验证聊天文本真伪、截图是否正确或人工清单是否认真审查。代理必须以实际证据执行，不能照抄示例答复来绕过确认。
